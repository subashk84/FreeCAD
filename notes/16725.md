# Issue 16725: Draft: When moving Draft_Mirrored elements to layer, source objects do not take over layer properties

## Outcome

**Fix ready for review** (with one design question for the maintainers).

The bug reproduces on weekly-2026.10.01. A layer only restyles the objects that are
directly in it. A mirrored object (`Part::Mirroring`) keeps its source nested under it
in the tree, but the source is not a member of the layer, so it keeps its own style.
The candidate fix makes the layer also restyle the source of a mirror that is in the
layer, in a deliberately narrow set of cases (see "The fix").

## What goes wrong, in plain words

- The user mirrors a rectangle with Draft Mirror. The tree shows "Rectangle (mirrored)",
  with the original "Rectangle" nested underneath it. Both halves are visible on screen.
- The user drags "Rectangle (mirrored)" onto a layer that has, say, red dashed lines.
- **Seen:** only the mirrored half turns red and dashed. The original half keeps its
  old colour and line style, although in the tree it now sits inside the layer.
- The original cannot be dragged into the layer on its own, because it is nested under
  the mirror (the reporter's point in the thread).
- **Expected (as the reporter and the "Confirmed" label suggest):** both halves look
  like the layer.

## Root cause

- `src/Mod/Draft/draftobjects/layer.py`, `Layer.onChanged()` (lines 125-140 on
  `origin/main` 7d2c421): when an object is added to the layer's `Group`, it calls
  `change_view_properties(..., targets=[child])` for that one object.
- `src/Mod/Draft/draftviewproviders/view_layer.py`,
  `ViewProviderLayer.change_view_properties()` (lines 211-271 on `origin/main`): it
  loops over `targets`, or over the layer's `Group` when the layer's own style is
  changed (line 255: `for target_obj in (targets if targets is not None else vobj.Object.Group)`).
  It restyles exactly those objects and nothing below them.
- The mirror's source is linked from the mirror's `Source` property and shown under the
  mirror by the mirror's own view provider. It is never in the layer's `Group`, so it
  is never in that loop.

Nothing is wrong in C++; the layer simply never looks at nested objects. The fix is
Python only.

## The fix

Branch `fix/16725-layer-mirror-source`, commit `bad2015`
("Draft: Apply layer style to the source of a mirrored object"), one commit on top of
`origin/main` 7d2c421.

What changed: before `change_view_properties()` restyles its targets, it adds the
source of every `Part::Mirroring` object among them, but only when **all** of these hold:

1. the mirror is the source's only parent (`source.InList` is exactly the mirror), so
   a source shared with another object (a second mirror, an array, a group) is left alone;
2. the source is not in any layer itself, so a source that the user already put in a
   layer keeps that layer's style;
3. the property being passed on is a style property (line colour, shape appearance,
   line width, draw style, and the point/text colour and point size derived from them),
   **not** Visibility. A source may have been hidden on purpose (Part's own Mirror tool
   hides it), and showing it again would change the model's appearance unexpectedly.

If the source is itself a mirror, its own source is followed the same way.

Because the change is in `change_view_properties()`, it covers both paths: dropping a
mirror on a layer, and later changing the layer's colour/width/style (including the
layer's "Reassign properties" menu entry). The existing "only change a child whose
value still equals the layer's old value" rule applies to the source too, so a
user-overridden colour on the source is respected exactly as it is for layer members.

Why this is the smallest change: one function gets a few lines, one helper is added,
the layer's `Group` contents and the file format are untouched, and objects other than
mirrors behave exactly as before.

Other approaches considered:

- **Restyle every child the object shows in the tree (`claimChildren`)**: would also
  cover arrays, extrusions, booleans, etc. Rejected for now: those bases are usually
  hidden and often shared, and restyling them is a wider behaviour change that a
  maintainer should decide on.
- **Add the source to the layer's `Group` as well**: makes the source a real layer
  member, but changes what the layer contains and how the tree shows it (the source
  would appear twice), and `Group` changes are saved in the file.
- **Make Draft Mirror format the source when the mirror is created**: does not help
  existing files and does not follow later layer changes.
- **Do nothing / documentation only**: the position first taken in the thread ("move
  the base object to the layer too"). The reporter showed that is not possible once the
  base is nested, which is why this fix exists.

## The diff, explained line by line

`src/Mod/Draft/draftviewproviders/view_layer.py`, in `change_view_properties()`:

- `- for target_obj in (targets if targets is not None else vobj.Object.Group):` — the
  old loop header; it chose the objects to restyle and looped in one line. Replaced so
  the list can be extended first.
- `+ if targets is None:` / `+ targets = vobj.Object.Group` — same choice as before: the
  given objects, or all layer members when none were given.
- `+ # The source of a mirrored object ...` (3 comment lines) — explain why sources are
  added and why Visibility is excluded.
- `+ if prop != "Visibility":` — skip the extra objects when only visibility is changing.
- `+ targets = targets + self._get_mirror_sources(targets)` — add the qualifying mirror
  sources to the list of objects to restyle (a new list; the layer's `Group` is not modified).
- `+ for target_obj in targets:` — the loop itself, unchanged in behaviour.

New method `_get_mirror_sources()` in `ViewProviderLayer`:

- `def _get_mirror_sources(self, objs):` and the docstring — a helper that returns the
  sources to restyle and states the two conditions.
- `sources = []` — collects the result.
- `for obj in objs:` — look at every object being restyled.
- `while obj.TypeId == "Part::Mirroring":` — only mirrors; the loop continues down a
  chain of mirrors of mirrors.
- `src = obj.Source` — the object being mirrored.
- `if src is None or src in sources or set(src.InList) != {obj}: break` — stop if there
  is no source, if it was already collected, or if anything other than this mirror uses it.
- `if get_layer(src) is not None: break` — stop if the source is already in a layer.
  (`get_layer` was already imported in this file.)
- `sources.append(src)` / `obj = src` — keep it, then check whether it is a mirror too.
- `return sources` — hand the list back.

`src/Mod/Draft/drafttests/test_layer_gui.py` (new): the four tests listed below.

`src/Mod/Draft/TestDraftGui.py`: two lines that import the new test class as
`DraftTestGui07`, following the pattern of the six existing ones, so
`FreeCAD -t TestDraftGui` runs it.

`src/Mod/Draft/CMakeLists.txt`: one line that installs the new test file with the other

## Questions for the maintainers

The first maintainer reply in the thread questioned whether this is a bug at all; the
issue is now labelled Confirmed and a triager asked for a proposed solution. These
points are design decisions. **Needs a maintainer decision.**

1. **Should a layer style objects nested under its members at all?**
   - (a) No, behaviour stays as is (users must downgrade the mirror to restyle the base).
   - (b) Only the source of a mirror, when nothing else uses it and it is not in a layer.
     **This is what the fix implements.** It is the narrowest change that solves the
     reported case and leaves every other object type untouched.
   - (c) Every nested child (`claimChildren`) of a layer member: arrays, extrusions,
     booleans, clones, Part features. Wider fix for the same pattern; would also restyle
     hidden bases and could conflict when a base is shared.
   - (d) Make the source a real layer member (add it to `Group`).
   Under (c), the helper would walk `ViewObject.claimChildren()` instead of `Source`
   and the tests would need cases for the other object types.
2. **Should the layer's Visibility reach the source?** The fix says **no**, so hiding the
   layer leaves the original half of a Draft mirror visible (as today). The alternative
   hides it too, but would also *show* a source that the user (or Part Mirror) hid on
   purpose whenever the layer is shown. A middle ground (only hide, never show) is
   possible but needs more state.
3. **Shared sources.** A source used by two mirrors (or a mirror and something else) is
   left alone. The alternative "last layer wins" would make the source's style depend
   on the order of drops.
4. The linked related report (layer Shape Appearance not reaching children, quoted in the
   thread from another issue) is a different problem — see "Other problems noticed".

## Not verified

- Only Linux, weekly-2026.10.01, in a virtual display (xvfb). Not tested on Windows
  (the reporter's platform) or macOS.
- No real mouse drag in the tree; the scripts call `dropObject()`, which is what the tree
  calls. The tree-drag workaround code (`canDragObject`/`update_groups_after_drag_drop`) was not exercised.
- The screen was not looked at; results are read from view properties. The "Check it by
  hand" steps have **not** been run by me.
- Save and reopen (step 10) not tested by script.
- Mirrors of mirrors (the chain in the helper) not covered by a test.
- Moving a mirror from one layer to another, or out of a layer, not tested.
- Draft_AutoGroup (creating a mirror while a layer is active) not tested.
- `Part::Mirroring` objects made with the Part workbench's Mirror tool not tested
  (its source is normally hidden; the style change is invisible until shown).
- Performance with very large documents: `get_layer()` searches the document once per
  mirror source on every layer style change. Not measured.
- The `CMakeLists.txt` change was not built.

## Other problems noticed

- From the thread: changing a layer's Shape Appearance (colour, transparency) does not
  reach the objects in it (the related report a maintainer linked). Not investigated
  here; possibly linked to how `_app_material_is_same()` compares materials or to the
  `OverrideShapeAppearanceChildren` setting.
- From the thread: a mirrored object placed on a TechDraw page through a group or a
  layer behaves unexpectedly (reporter's second video). Not investigated.
- `layer.py` `removeObject()` uses `if not child in grp` (style nit, would be `not in`). Not changed.
